💡 **What:** Replaced the sequential `saveExercise` calls (an N+1 API call pattern) in `handleSwitchExercise` with a single, bulk `saveExercises` method that sends multiple exercise definitions in one `/bulk` API payload. Also updated the benchmark to properly simulate the N+1 behavior (for-of loop vs single bulk promise).
🎯 **Why:** Performing multiple singular `POST` requests in rapid succession or using `Promise.all` with individual HTTP requests introduces network round-trip overhead for every item. Batching these updates dramatically reduces latency.
📊 **Measured Improvement:** The `benchmark.js` simulation (with a 50ms latency floor for an HTTP request) showed the N+1 pattern taking `1006.84ms` for 20 items, while the parallel bulk insert took `50.50ms` (a ~20x performance increase).
